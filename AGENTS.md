# AGENTS.md — Cognitwin Workspace Governance & Engineering Rules

> **Single Source of Truth for Autonomous Agents & Teammate Workflows**  
> *Cognitwin: Adaptive Cognitive Digital Twin for Personalized Learning (Paper 1 Build Scope)*

---

## 1. Core Operating Directives

1. **Strict Phase Gating (NEVER Jump Ahead)**:
   - Execution is divided into five strictly ordered phases:
     - **Phase 1**: Monorepo skeleton, Docker Compose (PostgreSQL), path-filtered CI/CD, lint/test tooling, health checks.
     - **Phase 2**: Landing Page + Auth & RBAC (`student` vs `researcher`) with HTTP-only cookies.
     - **Phase 3**: Privacy-first Manifest V3 Chrome Extension (Study Mode ON/OFF, active focus filtering, batched sync).
     - **Phase 4**: Concept catalog, URL-to-concept mapper, and in-app Quick Verification Quiz engine.
     - **Phase 5**: PyTorch Geometric GNN-KT inference service, live React Flow Digital Twin graph, and Researcher Paper 1 metrics view.
   - **Rule**: Never create, scaffold, or test code for Phase $N+1$ until Phase $N$ tests pass, static checks pass, exit criteria are documented, and the human user explicitly approves moving forward.

2. **Paper 1 vs Paper 2 Scope Boundary**:
   - **Paper 1 (ACTIVE BUILD SCOPE)**: Graph-based Knowledge Tracing (GNN-KT) modeling concept mastery and forgetting risk from dual-signal telemetry (passive study exposure + active verification attempts), visualized via an interactive React Flow Digital Twin and evaluated with AUC/RMSE metrics.
   - **Paper 2 (FUTURE SEAM ONLY — DO NOT BUILD YET)**: Reinforcement Learning (RL) intervention policy and LLM-powered dynamic content generation.
   - **Rule**: Do NOT write RL agents, policy networks, LLM generation pipelines, or prompt engineering modules. ONLY define clean, decoupled seams in the database (e.g. `interventions` audit table placeholder) and REST API contracts.

3. **Dual-Signal Digital Twin Integrity**:
   - **Passive Exposure (`passive_exposure`)**: Measures active dwell time and recency from technical documentation, whitepapers, and videos. It slows the forgetting decay curve; it **NEVER** directly marks a concept as verified or masterable.
   - **Active Verification (`quiz_attempt`)**: Ground truth generated by targeted in-app 2-minute micro-checks (correctness, latency, attempt count, difficulty). This serves as the primary update signal for GNN-KT node mastery probabilities.

## 3. Engineering & Coding Standards

### 3.1 TypeScript & Frontend (`apps/web`, `apps/extension`)
- Strict type checking (`"strict": true` in `tsconfig.json`). Never use `any` unless wrapping an untyped 3rd-party library (must be documented with an inline comment).
- Component styling strictly adheres to `docs/DESIGN_SYSTEM.md`: 8px max border radius (`rounded-lg`), crisp 1px borders (`border border-slate-200`), no dark neon cyberpunk aesthetics.
- State management: Use clean React hooks (`useState`, `useReducer`, or lightweight Zustand if shared across non-tree components).
- Vite development server proxies `/api/*` to `http://localhost:8000` to prevent CORS issues with credentials.

### 3.2 Python & Backend Services (`services/api`, `services/gnn_kt`)
- Python 3.11+ with strict type hinting on all function signatures (`def func(param: str) -> ReturnModel:`).
- Linter and formatter: `ruff` for linting and code formatting; `mypy` for static type checking.
- Pydantic v2 schemas for all API inputs and outputs (`response_model` required on every public route).
- Asynchronous database operations using `asyncpg` and SQLAlchemy async sessions (`AsyncSession`).
- No bare `except:` blocks. Specific exception handling with structured HTTP error codes and informative error bodies.

### 3.3 PyTorch Geometric & Machine Learning (`services/gnn_kt`)
- All PyG tensor operations must be dimension-checked and tested against variable batch sizes.
- **Cold-Start Guarantee**: When a user has zero exposure or attempt history, the system must initialize a deterministic baseline prior (e.g., $P(\text{mastery}) = 0.5$, $\text{forgetting\_risk} = 0.0$). Tensor representations must never output `NaN`, crash on empty edges, or throw unhandled zero-length graph exceptions.

## 4. Security & Privacy Rules

1. **Authentication & Session Tokens**:
   - Access tokens stored exclusively in **HTTP-only, Secure, SameSite=Lax** cookies for web client sessions.
   - Do **NOT** store JWTs in browser `localStorage` or `sessionStorage` in `apps/web`.
   - The browser extension communicates with the API using a scoped Bearer API token issued from the authenticated web session and stored in `chrome.storage.local`.
2. **Role-Based Access Control (RBAC)**:
   - FastAPI dependencies must enforce roles:
     - `get_current_active_user`: Validates authentication.
     - `require_role("student")`: Accessible by students and researchers.
     - `require_role("researcher")`: Strictly researcher-only access to evaluation datasets, aggregate AUC/RMSE metrics, and model weights.
3. **Telemetry Privacy Safeguards (The Extension Contract)**:
   - The Chrome extension **NEVER** captures or transmits page DOM, HTML body text, input fields, passwords, or personal chat messages.
   - The extension only captures:
     - Sanitized URL domain & path (stripped of auth queries/tokens).
     - Page `<title>`.
     - Active focused dwell time (seconds with active mouse/keyboard focus).
     - Media duration & playback time (for educational YouTube video URLs).
   - Strict blocklist applies: banking, social media, webmail, and private intranets are ignored even if Study Mode is toggled ON.

## 5. Git & Collaboration Discipline

1. **Branch Naming**:
   - `phase-<N>/<feature-slug>` (e.g., `phase-1/monorepo-skeleton`, `phase-2/auth-and-landing`, `phase-3/extension-telemetry`).
2. **Conventional Commits**:
   - `feat: <description>` — New feature.
   - `fix: <description>` — Bug fix.
   - `docs: <description>` — Documentation only.
   - `test: <description>` — Adding or updating tests.
   - `ci: <description>` — GitHub Actions or workflow changes.
   - `chore: <description>` — Tooling, dependencies, or configuration.
3. **No Secret Leaks**:
   - Never commit `.env` or production secrets. Always commit clean `.env.example` templates with sensible local defaults.
4. **CI/CD Path Filtering**:
   - Frontend PRs must not trigger PyTorch builds. Every workflow in `.github/workflows/` must declare strict `paths:` filters.
